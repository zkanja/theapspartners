§ 01 · Doctrine How the practice works

Root cause, in writing.

Most consultants ship fixes. This practice ships verdicts — by-design or defect, proven in hours, documented so the client keeps a better-understood solution than before the incident.

i.

Hypothesis before build

Every anomaly starts as a falsifiable hypothesis against the existing setup — never a rebuild reflex. The cheapest fix is the one you prove you don't need.

ii.

Read every layer

Maestro alone never tells the full story. The file is only closed once SAP (MD04, MM03, EKET/EKPO), the BW extractors, the middleware mappings and the Maestro data model agree on one narrative.

iii.

By-design vs defect, fast

A wrong escalation costs weeks of vendor ping-pong. Written proof — the spec paragraph, the field trace, the reproducible case — closes files in days, not quarters.

iv.

Every incident becomes a pattern

Each root cause is codified into an anonymised, reusable diagnostic pattern. The practice compounds; the client's documentation compounds with it.

§ 04 · Casework Four closed investigations · anonymised
CASE / AConfiguration

The transfer that lost its transit time

Symptom

Planned stock transfers at a global manufacturer started on their due date — transit time had silently vanished from every start date.

Trace

Order policy semantics against the date chain: with Lead Time Override = Yes every date is read from the order record — you cannot override one segment and keep the rest computed.

The call

Not a defect. Three settings interact: variable lead time, constraint date rule, order policy. One combination reproduces SAP exactly.

Outcome

Dates aligned with SAP in production; the written trace became the team's reference note on transfer dating.

CASE / BBy-design

The defect that wasn't

Symptom

Purchase proposals came out at twice the lot size. The planning team suspected a Maestro calculation defect and prepared a vendor escalation.

Trace

Side-by-side of SAP MRP rounding rules (MM03) against Maestro's strict Max > Min > Multiple precedence on the same part master.

The call

By-design on both sides — the two engines round differently by specification. Written proof delivered the same day.

Outcome

Escalation closed in under a day. Weeks of vendor ping-pong avoided; master data harmonised instead.

CASE / CDefect · proven

The bug only production could see

Symptom

An end-of-life legacy planning tool — no vendor support left — produced intermittently wrong demand-review figures for a month. Top management watching.

Trace

Same query replayed against QA and production, then down through the integration pipeline to the code: a hard-coded filter misclassifying future order book on one distribution channel.

The call

Defect — proven at the exact line of code, with the reproducing dataset attached.

Outcome

Fix routed to the right team with line-level proof. A month of doubt closed by one written trace, solo.

CASE / DConfiguration

Eight allocations where one belonged

Symptom

An allocation workbook multiplied records ×8 — every run created phantom lines the planners had to clean by hand.

Trace

Composite worksheet design: three ungrouped data sources fanning out as a cartesian product — 2³ = 8, the arithmetic signature of the layout itself.

The call

Authoring configuration, not data corruption: group the component sources and the fan-out collapses.

Outcome

One checkbox per source. Verified the same day; the pattern now guards every composite review.
